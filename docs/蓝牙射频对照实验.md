# 蓝牙射频对照实验工作树

工作目录：`D:\PPGtoHR_data\.worktrees\ble-rf-control`，分支 `codex/ble-rf-control`。
基于主工作区当前源码（包括未提交的统一 UI、无 PPG 模式）建立。主区采集程序、录制文件与固件源码未修改；本工作树复用主区 Python 和工具链，只读使用，不复制或安装依赖。

## 使用

1. 完成正在进行的采集后，停止录制并断开主窗口串口连接。
2. 双击本工作树根目录 `start.bat`，进入“固件配置与烧录”，标题为“蓝牙射频对照 · 独立工作树”。
3. 默认选择“不使用 PPG”“关闭射频实验 · 持续保持模块硬件复位”。确认与本轮实验的 PPG 设置相同；按实际硬件修改其他采集项。
4. 连接 ST-Link，点击“编译并烧录”。本次开发没有执行烧录或连接硬件。
5. 仅用有线接收，待启动稳定后录制。记录名与备注应标明 RF_OFF。此时 HJ-380 不应连接到本板；若仍连接，不要把这份数据当作射频已关闭。
6. 对照时把“蓝牙射频”改为“正常运行”，保持“蓝牙初始化关闭”，重新编译烧录；使用同样接线、供电、姿态及等待时间记录 RF_ON。RF_ON 还需记录 HJ-380 是否实际连接。

两份预编译固件也已生成：`build/rf-off/L452CEU6.elf` 与 `build/rf-on/L452CEU6.elf`（同时含 hex/bin）。它们均为无 PPG、100 Hz Raw、蓝牙初始化关闭，只改变 BLE_RF_DISABLED。SHA-256 和构建参数见 `build/rf-pair-manifest.json`。UI 使用 `build/desktop` 重新构建，不会误用两份预编译文件。

## 实现与边界

HJ-131IMH 软件手册 PDF 第 8 页（印刷 -4-）说明 h_RESET 为高电平有效复位。该实验使用现有 PB13/BLE_RST 连线，在 GPIO 初始化输出锁存器阶段设高，随后保持高电平；不发送休眠或恢复出厂指令。BLE_RF_DISABLED=1 同时阻止 BLE_Init/复位释放代码参与编译。ADC、传感器供电和共用 UART2 发送保持原样，确保有线仍有 100 Hz 数据。

这是**持续硬件复位实验，不是模块断电**，也不等于停止向共用 UART 发送：UART 仍在切换，模块仍有供电。预期模块在复位状态不运行 BLE 协议，但目前没有在本板实测；必须核查 PB13 及模块 h_RESET 引脚确实为高、模块不广播/不连接，条件允许时验证 RF/电流活动消失。MCU 上电到 GPIO 初始化之间、烧录和 MCU 复位期间不能保证该引脚一直有效，分析时去掉启动阶段。

若模块内部不支持持续复位抑制射频、引脚接错或存在其他驱动，需改用受控模块电源关闭；不能凭软件配置就宣布射频绝对为零。模块保持复位同时改变其数字活动与功耗，因此噪声下降只能支持 BLE 模块活动相关干扰，仍不能单独区分射频辐射与供电传导。

ENABLE_BLE_CONFIG=0 只表示不重新配置模块；BLE_RF_DISABLED=1 才是本次新增的保持复位控制。射频关闭时 UI 禁用初始化选项，构建参数也强制 ENABLE_BLE_CONFIG=0。恢复正常模式不会清除模块保存的配对或连接参数。

## 当前连接状态实验

插拔电脑端 HJ-380 可以改变连接状态；保持板子 USB、电池和姿态不动。拔掉 HJ-380 后板端 BLE 仍可能广播，此阶段不能称为“射频关闭”。建议有线连续记录每段约 30 秒并记下插拔时间。
