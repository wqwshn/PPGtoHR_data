# 新板通信检查方案

## 已确认的目标与范围

2026-10-17 用户确认：

- 面向新焊接、尚未烧录过 STM32 程序的 PCB，检查 MIMU、蓝牙、ADC、PPG 等关键器件。
- 可以连接 USB-TTL 查看检查结果。
- 仅进行基础通信检查，不增加采集响应、测量精度、标定或心率准确度验收。
- 流程尽量简单，按提示逐项检查，最后汇总通过与失败的项目。
- PPG2可检查或在未接小板时跳过，MAG不计入本次验收；自动逐项执行、复位重测，在烧录页直接看结果。

术语沿用仓库现有的 [CONTEXT.md](../../../CONTEXT.md)；通信通过的边界不扩大为功能正常。

## 现有代码约束

- `Core/Src/main.c` 的 ADC 启动检查会无限重试；MIMU 启动检查已被注释。初始化函数执行完毕不等于通信通过。
- `Core/Src/ADC_ADS124.c` 的旧身份检查仅检查 ID 的 bit0，不能直接沿用为严格通过条件，应避免把总线悬空读到的全 1 误报为通过。
- `Core/Src/MIMU.c` 已有加速度计/陀螺仪与磁力计身份读取，可分项报告。
- `Core/Src/ppg_channel.c`支持两路PPG总线；新板模式仅支持PPG2或跳过。
- 日志与蓝牙共用 USART2。`docs/在线心率算法实施文档.md` 记录过 USB-TTL TX 与 BLE TX 并接 STM32 RX 的问题。用户已确认两路TX硬件并接到PA3，无法断开；电脑只读不发送，但仍无法保证MCU回读可靠。
- 蓝牙初始化包含恢复出厂、改名和设置MAC；用户已确认该流程可恢复三板通信，新板模式现在显式提供开启/关闭，并复用已工作的同一实现。

## 已确认的流程与实现

用户确认最简流程后，按以下方式实现：

1. 使用独立的新板通信检查固件模式，与日常采集模式区分。
2. USB-TTL 仅接收日志：适配器 RX 接板端 USART2 TX（PA2），并共地；采用与板端相容的逻辑电平，本批硬件的适配器TX与蓝牙TX已并接PA3且无法断开，不要求更改接线，电脑端不发送数据。
3. 上电后提示并自动依次检查 MIMU、ADC、已装配的 PPG、蓝牙；不要求键盘交互，复位后可重新检查。
4. 每项在有限时间内完成检查，输出器件应答或身份值；失败后继续其他独立项目。依赖未满足的项目不得误报通过。
5. 蓝牙因硬件共享RX不执行MAC查询或波特率探测，标记MANUAL待人工确认；通过HJ-380的连接状态及实际数据接收另行验收。写配置不声称配置成功，不能从无回应判定模块故障。
6. 最后输出项目、通过/失败/跳过/待人工确认及简短原因的汇总；非装配项目明确标为不适用。
7. 新板模式提供PPG2/跳过和蓝牙初始化开启/关闭，屏蔽射频实验；内嵌检查串口、结果表和日志。MAG固定SKIP，统计PASS/FAIL/SKIP/MANUAL；原始数据页不解析检查报告。
8. 新板检查使用独立后台接收线程，固定115200/8N1，不发送命令。编译/烧录前释放串口，烧录成功后尝试连接所选检查串口；检查连接与采集/模拟互斥，模式切换及窗口关闭时释放资源。
9. 文本解析支持分块、波特率切换乱码和重复汇总，限制缓冲和日志长度；每轮汇总独立核对，缺失项目保持待检查，避免旧结果混入本轮。

## 检查依据

- MIMU A/G连续三次读取`WHO_AM_I=0x68`且HAL成功才通过；MAG固定跳过，不影响结果。
- ADS124S06：SPI 成功且 `(ID & 0x07) == 0x01`。高五位为保留位，不参与身份判断。依据 [TI 原厂手册表26](https://www.ti.com/lit/gpn/ADS124S06)。
- PPG2：检查寄存器读事务三个阶段的 ACK，要求 `PART_ID(0xFF)=0x15`；`REV_ID(0xFE)` 只显示，不硬编码判定。
- 蓝牙：开启初始化时先运行日常采集`BLE_Init()`，按已实测固定时序写配置，恢复出厂后19200配置，MAC重启后最后设置115200；关闭时保留配置。两种模式均不进行回读验证，结果为MANUAL，由HJ-380端到端数据确认；同一绑定MAC的板逐块上电核验。
- SPI单次等待最多50ms；蓝牙自动检查仅释放复位并提示人工确认，无串口等待窗口。单项失败继续后续器件，汇总每5秒重复。
- 检查结束释放蓝牙复位，允许实际无线验证；检查文本会进入共享UART，恢复Raw采集需烧录日常固件。
