# 固定 -10 dBm 无线采集

在工作树 start.bat 的固件页选择 **固定 −10 dBm · 启动复位后配置 / 持续采集**。默认已选择该项。保持“不使用PPG”和Raw 100 Hz，与上一轮一致。

启动后、传感器采样定时器启动前，向现有115200波特率的蓝牙模块发送一次 `<ST_TX_POWER=-10>`。发送之前先将PB13（BLE_RST，高电平有效）拉高100 ms，再拉低释放、等待300 ms启动；随后发送唤醒字节，等待2 ms，再发送功率指令，发送后等待100 ms。配置发生在释放复位之后，不能在持续保持复位时发送配置。没有恢复出厂、连接参数修改或功率查询。硬件复位沿用现有初始化流程的100/300 ms时序，启动时蓝牙连接会短暂中断并需重新连接。复位后仍使用模块此前保存的115200波特率；硬件复位不等于恢复出厂，也不能替代读回确认。若本地UART发送失败则进入错误处理，不继续假定启动成功。

此模式一直保持目标-10，不切换档位，也不在结束后恢复+2.5。每次MCU重启重新写一次。实际功率仍未读回验证，启动文本标明UNVERIFIED。旧的标准初始化和七段实验保留为独立选项；选择固定模式会禁用全量蓝牙初始化，防止其覆盖功率。

## 用户操作

1. 重新打开工作树入口，确认选择固定-10，编译并烧录。
2. 连接HJ-380无线COM，保持电池、USB插接状态、板子姿态、防风和dongle距离与上次七段采集一致。
3. 连接后尽早开始连续录制10–15分钟，不手动改变功率。保留早期数据，可观察预热漂移并与旧数据相近的上电时间段比较。
4. 停止后提供无线Raw及STATUS文件，并注明是否改变了供电或USB插接状态。固定模式不产生七段事件CSV，也没有COMPLETE倒计时。

上次功率没有读回，因此新旧对比是“目标-10”与“目标+2.5”的对照。不能仅凭一段噪声改善就排除时间变化，需同时观察33.3Hz频带、宽带波动、毛刺、基线漂移和无线丢包。

预编译产物：`build/ble-fixed-minus10/L452CEU6.elf`、`.hex`、`.bin`，SHA256清单在同目录`firmware-manifest.json`。UI编译路径为`build/desktop`。复现：`python scripts/build_power_experiment.py --fixed-minus10`。
