# MAX30101 采集策略评估与优化建议

> 依据当前固件配置、`docs/MAX30101寄存器配置说明.md`、`docs/MAX30101项目配置说明.md` 以及实测文件 `bug/一次多通道采集数据-PPG波形质量低问题/holdbreath1.csv` 整理。

## 1. 结论

当前硬件基础上，**可以在保留 Green+Red+IR 三路光谱同步采集的前提下，通过修改 MAX30101 采集策略提升 PPG 信号质量**。新的优先方向不是切到 Red+IR 双光路，而是把三路 Multi-LED 方案用好：保持同一 FIFO 样本帧内的 Green/Red/IR 时隙采集，同时给传感器输出率留出裕量、修正当前约 50Hz 有效 PPG 新样本率问题，并围绕 Red/IR 的 AC/DC 和漂移指标调参。

但也要明确边界：本次实验检测位置为**手腕背部**，该位置对红光/红外反射式 SpO2 天然不友好。实测 Red/IR 的脉动 AC/DC 只有约 `0.023% / 0.054%`，波峰波谷不明显不是链路丢包造成的，而是红/红外在该位置的脉动分量太弱、低频漂移相对过强。三路同步采集可以保留 Green 作为腕部心率/灌注参考，也能让 Red/IR 与 Green 在同一采样帧内对齐，但它不能保证腕背达到指夹/指尖血氧的可靠性。

## 2. 当前固件采集配置

当前默认编译配置来自 `Core/Inc/main.h`：

| 项目 | 当前值 |
|------|--------|
| 工作模式 | `CURRENT_WORK_MODE = MODE_HEART_RATE` |
| 数据模式 | `ENABLE_RAW_DATA_PACKET = 1` |
| PPG 通道 | `PPG_DEFAULT_CHANNEL = 2` |
| MCU 采样/发包标称频率 | `PPG_SAMPLE_RATE = 100` |

心率模式实际使用 `PPG_Config_Green_Hardcoded()`，不是单绿光，而是三光路 Multi-LED：

| 寄存器 | 当前值 | 含义 |
|--------|--------|------|
| `MODE_CONFIG (0x09)` | `0x07` | Multi-LED |
| `MULTI_LED_CTRL1 (0x11)` | `0x13` | SLOT1=Green, SLOT2=Red |
| `MULTI_LED_CTRL2 (0x12)` | `0x02` | SLOT3=IR, SLOT4=Disabled |
| `LED3_PA Green (0x0E)` | `0x91` | 约 29.0mA |
| `LED1_PA Red (0x0C)` | `0x81` | 约 25.8mA |
| `LED2_PA IR (0x0D)` | `0x81` | 约 25.8mA |
| `SPO2_CONFIG (0x0A)` | `0x56` | ADC=8192nA, SR=1000sps, PW=215us/17-bit |
| `FIFO_CONFIG (0x08)` | `0x7F` | 8x 平均, rollover, A_FULL=15 |

因此当前已部署三光路策略是：内部 1000sps，经 8x 硬件平均后理论输出 125sps，MCU 仍按 100Hz 轮询/发包。这里的“三路同步”指 MAX30101 Multi-LED 在同一 FIFO 样本帧内按 SLOT1->SLOT2->SLOT3 采集 Green/Red/IR，三路时间偏移由 LED 时隙决定，远小于 100Hz 包周期。

## 3. 实测数据质量评估

实测文件 `holdbreath1.csv` 共 `15115` 行，时间轴 `151.14s`，标称 100Hz。该数据采自旧基线 `0x52/0x7F`，用于说明部署前的问题。链路质量本身良好：

| 指标 | 结果 |
|------|------|
| `ValidFlag` | 全部为 1 |
| `InterpFlag` | 总和 0 |
| `GapLen` | 总和 0 |
| `MissingBefore` | 总和 0 |
| `Seq` | 全程连续递增 |

### 3.1 PPG 幅值和脉动分量

对三通道做 0.7-3.0Hz 心率带滤波后，得到：

| 通道 | DC 均值 | 占 17-bit 满量程 | 心率带 RMS | 心率带 AC/DC | 主峰 |
|------|---------|------------------|------------|--------------|------|
| Green | 6392 | 4.88% | 23.6 counts | 0.369% | 63.75 BPM |
| Red | 70491 | 53.78% | 16.0 counts | 0.023% | 63.75 BPM |
| IR | 98536 | 75.18% | 53.4 counts | 0.054% | 63.75 BPM |

解释：

- Green 的 DC 很低，但 AC/DC 比 Red/IR 明显高，更像腕部心率通道。
- Red/IR 的 DC 不低，说明光能和 ADC 码值不是完全不够；问题在于脉动 AC 相对 DC 太小。
- Red/IR 的心率峰在频谱中存在，但时域波峰波谷很浅，直接用于 SpO2 的 `AC_red/DC_red` 与 `AC_ir/DC_ir` 会非常敏感。

### 3.2 低频漂移强于心率脉动

低频段 0.08-0.5Hz 与心率带 RMS 比值：

| 通道 | 低频 / 心率带 RMS |
|------|-------------------|
| Green | 1.42 |
| Red | 2.05 |
| IR | 1.77 |

这解释了“波形特征不显著”：红光/红外的脉动成分本来就小，同时慢漂移比心率波更强，时域曲线很容易被基线变化、贴合压力变化、呼吸/血流慢变化淹没。

### 3.3 实际 PPG 新样本率不足 100Hz

虽然 CSV 的 `Seq` 每行递增，100Hz 包完整，但三通道 PPG 数值大约每 2 行才变化一次：

| 指标 | 结果 |
|------|------|
| 任一 PPG 通道变化次数 | 7515 次 |
| 等效 PPG 新样本率 | 约 49.7Hz |
| 三通道完全相同值的连续 run 中位数 | 2 行 |
| 未变化转移比例 | Green 54.7%, Red 55.6%, IR 52.3% |

这说明当前“MAX30101 理论输出 100sps + MCU 100Hz 轮询”的边界太紧。异步轮询下，主循环约一半周期读到 FIFO 空值，固件沿用上次有效均值。它不是本次 Red/IR 弱脉动的唯一原因，但会降低时间分辨率，也会误导上位机以为 PPG 是完整 100Hz。

## 4. 根因判断

当前问题更像是多因素叠加：

1. **实验位置高风险**：腕背反射式 Red/IR 的脉动分量弱，不是 SpO2 的理想采样位置。
2. **旧三路同步配置的输出率裕量不足**：旧 `0x52/0x7F` 为同时采 Green/Red/IR，100Hz 配置降到 215us/17-bit，并把内部平均后的输出率卡在理论 100sps。
3. **FIFO 输出率没有裕量**：内部平均后的输出率约等于 MCU 轮询率，实测产生约 50Hz 的重复 PPG。
4. **Red/IR 没有独立闭环调参**：当前电流较高，但没有根据 DC 目标、AC/DC、ALC_OVF、饱和余量做自动或半自动增益控制。
5. **SpO2 分析不应直接依赖当前这组未优化三路数据**：当前 Red/IR AC/DC 太低，直接计算屏气 SpO2 基准实验风险很高；但在三路同步目标下，应先优化 Multi-LED 采集链路，再评估 Red/IR 比值稳定性。

## 5. 推荐采集策略

### 5.1 第一优先级：保留三路 Multi-LED 同步采集

当前目标是优先采用三路光谱同步采集，因此建议继续使用 `MODE_CONFIG=0x07` 的 Multi-LED 模式，并保持：

| Slot | LED | 用途 |
|------|-----|------|
| SLOT1 | Green | 腕部心率、灌注强弱、运动/贴合参考 |
| SLOT2 | Red | SpO2 红光通道 |
| SLOT3 | IR | SpO2 红外通道 |
| SLOT4 | Disabled | 保持关闭 |

这个方向的好处是三路数据来自同一 FIFO 样本帧，便于比较 Green 与 Red/IR 的相位、幅度和运动干扰，也能避免不同模式、不同批次采集导致的贴合状态差异。Red+IR 血氧模式可以作为诊断对照，但不再作为主路线。

### 5.2 第二优先级：先解决三路同步下的 FIFO 输出率裕量

一句话：先用 0x56/0x7F 排除采样策略/FIFO 裕量问题，再用 0x73/0x5F 验证脉宽是否能进一步改善 Red/IR 波形。

不要让 MAX30101 平均后的输出率刚好等于 MCU 读取率。旧 `0x52/0x7F` 配置下 `800sps / 8x = 100sps` 与 MCU 100Hz 轮询过于贴近，实测导致约 50% 包复用旧 PPG。已部署的 `0x56/0x7F` 将输出率提升到 125sps，用于验证增加 FIFO 裕量是否能改善波形连续性。

优先候选配置：

| 优先级 | 名称 | 模式 | `SPO2_CONFIG` | `FIFO_CONFIG` | 数据位宽 | 预期 |
|--------|------|------|---------------|---------------|----------|------|
| 已部署 | GRI-100-v2 | G+R+IR | `0x56` | `0x7F` | 17-bit | 1000sps / 8x = 125sps，最小改动，优先验证能否消除 FIFO 空读 |
| 2 | GRI-100-v3 | G+R+IR | `0x52` | `0x5F` | 17-bit | 800sps / 4x = 200sps，输出率裕量更大，固件每包平均约 2 个 FIFO 样本 |
| 3 | GRI-100-v4 | G+R+IR | `0x73` | `0x5F` | 18-bit | 800sps / 4x = 200sps，提高脉宽/分辨率，但三路时隙占空接近上限 |
| 对照 | RI-100-diag | Red+IR | `0x6F` | `0x1F` | 18-bit | 仅用于诊断 Red/IR 在腕背位置的物理上限，不作为主采集路线 |

说明：

- `0x56` = ADC 8192nA、SR 1000sps、PW 215us；三路时隙 `3 x 215us = 645us < 1000us`，时序裕量较好，且仍可沿用当前 17-bit 解包宏。
- `0x52/0x5F` 保持当前 ADC 量程和 17-bit 位宽，只把硬件平均从 8x 降到 4x，使传感器输出率从 100sps 提到 200sps。
- `0x73/0x5F` = ADC 16384nA、SR 800sps、PW 411us；三路时隙 `3 x 411us = 1233us < 1250us`，理论可行但裕量很窄，功耗也更高。若启用该配置，固件解包需同步改为 18-bit：`MAX30101_PPG_RIGHT_SHIFT=0`、`MAX30101_PPG_VALID_MASK=0x03FFFF`。
- Red+IR 对照组的价值是判断“腕背位置本身是否能提供足够 Red/IR 脉动”，不是替代三路同步方案。

固件落点：上述主路线均应在 `Core/Inc/sample_rate_config.h` 的 `PPG_SAMPLE_RATE == 100` 分支修改 `MAX30101_SPO2_CONFIG_VAL` 和 `MAX30101_FIFO_CONFIG_VAL`；只有 `GRI-100-v4` 还需要同步修改 18-bit 解包宏。

### 5.3 第三优先级：建立三路同步调参指标

每次试验至少记录以下指标，并按窗口统计：

| 指标 | 建议目标 |
|------|----------|
| DC 占满量程 | 30%-80%，优先避免饱和 |
| Green 心率带 AC/DC | 用作腕部贴合/灌注参考，应保持稳定且主峰清晰 |
| Red/IR 心率带 AC/DC | 越高越好；低于 0.1% 时 SpO2 可靠性高风险 |
| 低频/心率带 RMS | 小于 1 更理想；大于 1 表示漂移盖过脉动 |
| FIFO 空读比例 | 应接近 0，不能像当前约 50% 周期复用旧 PPG |
| ALC_OVF | 必须为 0 |

调参顺序建议：

1. 固定佩戴压力和遮光条件，先复测已部署的 `GRI-100-v2`。
2. 如果重复 PPG 样本率仍高，再切到 `GRI-100-v3`，用更高输出率换取时间连续性。
3. 如果 Red/IR AC/DC 仍低且无饱和，再评估 `GRI-100-v4` 的 411us/18-bit 配置。
4. 如果 DC 低且无 ALC_OVF，逐步提高对应 LED 电流；如果 DC 高但 AC/DC 仍低，不要只继续加电流，优先调整佩戴位置、压力、遮光、ADC 量程和脉宽。
5. Green、Red、IR 分别调，不要默认同一电流。目标是三路都有稳定脉动，Red/IR 可用于比值分析，Green 可作为贴合和运动参考。

### 5.4 第四优先级：改进记录与诊断字段

为后续判断“参数是否真的改善”，建议在 Raw 记录或 STATUS 中增加：

- 本周期 `sample_count` 或 `ppg_fifo_empty_counter` 的同步导出。
- 每通道当前寄存器配置快照：`MODE_CONFIG`、`SPO2_CONFIG`、`FIFO_CONFIG`、LED PA。
- ALC_OVF / PPG_RDY / A_FULL 状态统计。
- 实验事件 marker：开始屏气、结束屏气、恢复稳定。

当前 CSV 没有事件 marker，屏气 45s 只能按“中间约 45s”估算，不适合做严肃的 SpO2 延迟和幅度标定。

## 6. 建议实验矩阵

每组至少采集 2-3 分钟，包含静息、屏气、恢复，并同步记录参考指夹血氧仪。

| 组别 | 目的 | 配置 | 判断标准 |
|------|------|------|----------|
| A | 旧基线对照 | 旧 HR 三光路 `0x52/0x7F` (`holdbreath1.csv`) | 确认 Red/IR AC/DC 与重复样本率 |
| B | 已部署三路最小改动提速 | `MODE_MULTI`, `0x56/0x7F` | 100Hz Raw 中 PPG 是否不再每两行重复 |
| C | 三路高输出率 | `MODE_MULTI`, `0x52/0x5F` | FIFO 空读是否消失，Red/IR AC/DC 是否提升或至少更连续 |
| D | 三路 18-bit 对照 | `MODE_MULTI`, `0x73/0x5F` | 在时序裕量很窄的情况下，Red/IR 波形是否因 411us/18-bit 改善 |
| E | LED 电流矩阵 | 固定 B 或 C，分别扫 Green/Red/IR PA | 找到 Red/IR AC/DC 与 DC 余量的平衡点 |
| F | Red+IR 诊断对照 | `MODE_SPO2`, `0x6F/0x1F` | 仅判断腕背位置 Red/IR 物理上限，不替代三路同步路线 |
| G | 位置对照 | 同 B/C，换指尖或腕掌侧 | 判断硬件/位置上限 |

判定优先级：

1. 先看 FIFO 空读/重复样本是否显著下降。
2. 再看 Red/IR 心率带 AC/DC 是否超过当前 `0.023% / 0.054%`。
3. 同时看 Green 主峰是否稳定，避免为了 Red/IR 牺牲三路同步中的心率/贴合参考。
4. 再看屏气段 R 值 `(AC_red/DC_red)/(AC_ir/DC_ir)` 是否稳定、是否与参考血氧变化方向一致。
5. 最后才讨论 SpO2 绝对值公式和标定。

## 7. 对当前硬件可行性的判断

在不改硬件的前提下，值得继续优化采集策略，原因是：

- 当前 Red/IR DC 还没有完全饱和，说明仍有 ADC 量程、脉宽、输出率、平均策略可调。
- 旧默认三路配置存在输出率裕量不足问题，且 100Hz 包中约半数 PPG 值复用旧样本；当前已部署 `0x56/0x7F` 用于优先验证这一点。
- 当前数据证实链路没有丢包，后续参数对比可以直接看传感器质量指标。

但需要设置预期：

- 腕背 Red/IR 反射式 SpO2 很可能仍弱于指尖/耳垂，硬件佩戴结构和检测位置可能成为最终瓶颈。
- 如果按上述三路同步配置和佩戴优化后，Red/IR AC/DC 仍长期低于 0.1%，则应考虑更换检测位置、增强遮光/压紧结构，或把当前腕背三路方案定位为心率/趋势检测与多光谱研究数据，而不是可靠血氧绝对值测量。

## 8. 推荐下一步

1. 保留 `MODE_MULTI` 和 Green/Red/IR slot 顺序，当前已部署 `GRI-100-v2`：`SPO2_CONFIG=0x56`、`FIFO_CONFIG=0x7F`。
2. 烧录后在同一腕背位置复测一次静息+屏气+恢复，并同步记录参考指夹血氧仪和事件 marker。
3. 复测后只比较四个指标：重复 PPG 样本率、Red/IR AC/DC、Green 主峰稳定性、低频/心率带 RMS。
4. 若重复样本仍明显，进入 `GRI-100-v3`：`0x52/0x5F`。
5. 若时间连续性改善但 Red/IR AC/DC 仍低，再评估 `GRI-100-v4`：`0x73/0x5F`，同时修改 18-bit 解包宏。
6. Red+IR `MODE_SPO2` 只作为诊断对照组，用来判断腕背位置是否存在物理上限，不作为当前主方案。
