# 新板通信检查

适用于与当前工程硬件一致的新焊接 STM32L452CEU6 板：使用现有8MHz外部晶振配置，核验MIMU A/G、ADS124S06和可选PPG2；HJ-131IMH需经HJ-380人工确认。MAG固定跳过，未接PPG小板时可选跳过。PASS表示取得有效身份或应答，不代表采集、精度、光路或无线透传性能合格。

## 操作

1. 板子按设计正常供电，用 ST-Link 连接 SWD。烧录方法沿用 [统一工作台使用说明](../统一工作台使用说明.md)。
2. USB-TTL 使用与板端相容的逻辑电平：适配器 **RX 接 PA2（STM32 TX）**，GND 共地。用户确认本批PCB的USB-TTL TX和蓝牙TX已在硬件上并接到PA3，实操无法断开其中一路；不再要求TX悬空，也不将PA3回读作为验收依据。电脑端保持只读、不发送数据；软件只读并不会解除硬件并接。
3. 打开 `start.bat`，进入“固件配置与烧录”，选择“新板通信检查”。未接PPG小板时将PPG通道选为“不使用PPG”，已连接时选PPG2。在下方选择USB-TTL COM口，未显示时点击“刷新串口”。
4. 选择合适的 SWD 速度，点击“编译并烧录”。烧录成功后会自动连接所选检查串口；已经烧录检查固件的板子可直接点击“连接检查串口”。串口参数固定为 **115200、8N1、关闭流控**，无需额外串口助手。
5. 已完成初始化的板子保持“蓝牙初始化=关闭”。真正首次使用或需要重新配置的板子，先选择“开启”烧录一次，再选择“关闭”重新烧录验证，流程见下节。不要对已正常通信的板子反复恢复出厂。
6. 连接后复位板子，启动提示后自动检查，显示“待检查 / 检查中 / 通过 / 失败 / 跳过 / 待人工确认”和对应总数。蓝牙始终待人工确认，不计入通过或失败。结果每5秒重复，不需要发送字符、转动板子或放手指。

## 蓝牙首次初始化与后续验证

依据用户三块实板已经验证的数据采集流程，新板检查现在直接复用 `main.c` 的 `BLE_Init()`：兼容当前115200，恢复出厂后切到19200/8N1继续配置，设置清密码、FOREVER唤醒、+2.5dBm、项目名称、最小连接间隔、项目绑定MAC；MAC设置导致模块重启后，最后设置波特率115200。具体命令及复位/等待时序沿用已有采集初始化，避免重新实现一套不同参数。

- **开启初始化**：每次上电都会恢复出厂并写入项目参数，不是“只执行一次”的持久标记。沿用已验证的固定写入时序，不依赖回读；本项输出`MANUAL / SETUP_UNVERIFIED`，仅表示尝试执行配置流程，不证明模块接收或保存成功。完成一次后请关闭初始化重烧。
- **关闭初始化**：保留模块当前参数，不再发MAC查询、不再为了探测切换19200/115200，也不按RX=0判定失败。本项输出`MANUAL / CONFIG_PRESERVED`，等待HJ-380确认。
- 检查结束保持BLE复位引脚低电平、允许模块运行。日志使用115200，并会沿共享串口进入模块；HJ-380若能持续收到本轮检查文本，是端到端传输证据，但文本不属于Raw采样。正常采集验收需烧录日常固件，并从HJ-380持续收到有效数据帧。
- HJ-380的连接状态仅作为辅助证据；同时记录是否持续收到了当前板的数据。连接命令已发送、指令应答或状态灯单独不能证明有效数据透传。检查页不自动把外部观察改写为PASS，后续人工结果另记入工作日志。
- 项目初始化写入固定`BLE_CUSTOM_MAC`，多块板使用同一绑定地址时无法靠该MAC区分板号；逐板上电验证，并记录板号、HJ-380 COM口、连接状态和实际接收结果。三块板已由用户确认蓝牙正常，保持初始化关闭即可。

检查串口由后台线程只读接收，不发送命令或 MAC 绑定指令。连接前会停止工作台已有采集；录制进行中会要求先停止录制。检查串口连接期间禁用采集和模拟操作，编译/烧录前自动断开检查串口；切回日常采集模式、断开或关闭工作台也会释放串口。不要让其他窗口或程序同时占用同一 COM 口。

## 调试日志

每次连接自动保存到项目 `.local/logs/`：`board-check-时间戳.log` 为可阅读的UTF-8日志，包含串口、当前选择、本地构建信息及连接/错误/关闭事件；同名 `.bin` 保存USB-TTL实际接收的完整字节，方便检查乱码。接收数据实时刷新到文件，未换行的末尾也会保存，不必等五项检查完成。日志中的构建清单仅证明本地编译信息，不证明设备已烧录该版本。

“复制完整日志”从已保存文件复制，不受界面1000行上限影响；“打开日志”可查看完整文件，“打开日志目录”定位其目录。编译与烧录日志也提供相同按钮。收到新数据时保留正在选中的文本和滚动位置。

后续可直接读取 `.local/logs/latest-board-check.json` 定位最新检查会话，无需从UI复制。实板反馈与待排查事项记录在[新板调试工作日志](../development/新板调试工作日志.md)。日志功能更新只需重新打开工作台，无需重新烧录；旧版未落盘的历史输出不能追溯恢复。

| 项目 | 通过条件 |
|---|---|
| MIMU ACC/GYRO | 连续三次SPI成功且`WHO_AM_I=0x68`，显示每次实际值 |
| MIMU MAG | SKIP，不作为当前验收门槛 |
| ADC ADS124S06 | SPI 成功，ID 低三位为 `001`；全 `0xFF` 不会通过 |
| PPG2 MAX30101 | 可选SKIP；启用时要求IIC2 ACK完整且`PART_ID=0x15` |
| BLE HJ-131IMH | MANUAL，待HJ-380连接状态及实际数据接收人工确认，不计通过/失败 |

PPG1标为`NOT_TESTED`，不计入五项结果。仅开启首次初始化时，写配置阶段会切换串口参数，可能有短暂乱码；自动检查阶段不再探测蓝牙波特率。每次启动或新汇总均清空本轮结果，缺失项目保持待检查；跳过项不计为失败。汇总包含PASS/FAIL/SKIP/MANUAL，兼容旧检查固件的无SKIP或无MANUAL报告。正常采集仍需烧录“日常数据采集”固件。

## 如何理解失败

- `SPI=0` 表示 HAL 传输完成，身份值仍须匹配；非0表示 SPI 传输错误或超时。
- MIMU/ADC 失败：结合实际 ID 检查供电、复位、片选及 SPI 焊接。全0或全1只是排查线索，不能据此直接断定芯片损坏。
- PPG2 的 `NO_ACK/BUS_LOW`：检查供电、IIC2 上拉、SCL/SDA 是否被拉低及焊接；只检查第二路。
- 蓝牙待人工确认：本批硬件PA3并接使MCU回读不可靠。旧日志的`RX=0`、`RX_ERROR`或MAC查询失败不能单独用于诊断模块故障；新固件取消该判定。按上述流程核验HJ-380连接与实际数据接收，失败后再排查配置、供电或无线链路。
- 完全没有文本：先核对本页串口连接状态、COM 口、RX 接线、共地及固件用途；再检查 ST-Link 烧录校验、MCU供电/复位和外部晶振。底层启动失败时无法保证输出报告。

## 开发与验证

`ENABLE_BOARD_CHECK`默认0；检查模式允许`ENABLE_BLE_CONFIG=0/1`，禁止与蓝牙实验宏并用，`PPG_DEFAULT_CHANNEL`允许0或2。独立构建目录`build/board-check-init/`为开启初始化、跳过PPG，`build/board-check-verify/`为关闭初始化、跳过PPG；工作台仍输出至`build/desktop/`。构建不等于已烧录，实际设备结果需接板确认。

自动测试使用 Clang wasm32 和 Node 模拟 HAL，直接执行实际检查代码，覆盖器件身份、超时、无ACK、继续后续项目、实际初始化写入时序、禁用UART查询及蓝牙人工确认。缺少这两个工具时对应模拟测试跳过；硬件烧录和真实器件结果需另行接板验证。

上位机测试另行覆盖分块文本、波特率切换乱码、重复/不完整汇总、串口打开失败及拔出、只读接收、采集互斥、烧录前释放/成功后连接，以及关闭时线程和串口释放。
