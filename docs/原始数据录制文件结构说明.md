# 原始数据录制文件结构说明

本文说明每次 Raw 数据录制生成的文件集合、各字段语义，以及**蓝牙丢包在记录数据中的具体体现方式**。

---

## 1. 录制文件集合

每次点击“开始录制”前，用户先在“实验信息”中填写保存根目录、场景、试次、受试者缩写和实验日期。系统生成以下目录及同 stem 的文件：

```text
<保存根目录>\YYYYMM-multiperson\MMDD-SUBJECT\
```

主文件命名为：

```text
<scenario><trial>_<SUBJECT>_<MMDD>.csv
```

例如，在开机场景录制时可得到 `kaiji1_LYX_0710.csv`。其中 `kaiji` 是“开机”场景的稳定 token，表示记录传感器开机时长内的信号；仍须由用户手动点击“录制”开始。

| 文件 | 内容 | 采样率 |
|---|---|---|
| `<scenario><trial>_<SUBJECT>_<MMDD>.csv` | 主数据文件，100Hz 设备样本轴，缺失样本以 `NaN` 占位 | ~100 Hz |
| `<scenario><trial>_<SUBJECT>_<MMDD>_status.csv` | 1Hz 固件诊断快照 + PC 端链路统计 | 1 Hz |
| `<scenario><trial>_<SUBJECT>_<MMDD>_markers.csv` | 用户手动标记点记录，与主数据时间轴同步；仅在至少一次点击 marker 后生成 | 按需 |

不再生成早期的 `_timeline.csv` 和 `_quality_events.csv`。时间轴补齐与 gap 标记已合并到主 CSV，gap 事件信息由主 CSV 的 `ValidFlag`、`GapLen`、`MissingBefore` 和 `_status.csv` 共同描述。

## 2. 主数据文件：`<scenario><trial>_<SUBJECT>_<MMDD>.csv`

### 2.1 文件定位

这是下游算法应优先读取的原始数据文件。每行对应 100Hz 设备样本轴上的一个采样点。**收到有效数据时写入真实传感器值，未收到时显式写入 `NaN` 占位行**，保证时间轴连续。

### 2.2 完整字段说明

| 列 | 字段名 | 类型 | 说明 |
|---|---|---|---|
| 1 | `Time(s)` | float | 设备样本轴时间，由 `SampleIndex / 100Hz` 换算。**不是 PC 端的 wall-clock 接收时间**，因此不受蓝牙延迟抖动影响 |
| 2 | `SampleIndex` | int | 100Hz 样本轴索引，从 0 开始连续递增（含缺失行） |
| 3 | `Seq` | int | 固件侧 16 位 Raw 帧序号，范围 0~65535，溢出后回绕。真实行写入收到的实际序号，缺失行写入推算序号 |
| 4 | `ValidFlag` | 0/1 | **核心质量标记**。`1` = 真实收到且通过校验的有效样本；`0` = 因序号缺口补出的占位行 |
| 5 | `InterpFlag` | 0 | 当前始终为 `0`，表示缺失行仅做占位，不做自动插值 |
| 6 | `GapLen` | int | **仅在缺失行有效**：该行所属 gap 的总缺失样本数。真实样本行填 `0` |
| 7 | `MissingBefore` | int | **仅在真实行有效**：当前真实样本之前由 `Seq` 缺口推断出的连续缺失样本数。缺失行填空字符串 |
| 8-11 | `Uc1(mV)`, `Uc2(mV)`, `Ut1(mV)`, `Ut2(mV)` | float | 桥压传感器四通道，单位 mV |
| 12-14 | `AccX(g)`, `AccY(g)`, `AccZ(g)` | float | 加速度计三轴，单位 g |
| 15-17 | `GyroX(dps)`, `GyroY(dps)`, `GyroZ(dps)` | float | 陀螺仪三轴，单位 dps |
| 18-20 | `PPG_Green`, `PPG_Red`, `PPG_IR` | float | PPG 三通道原始 ADC 码值（绿光/红光/红外）。固件以 Q4 固定小数发送 FIFO 均值，上位机除以 16.0 后保存，因此允许出现 `.0625` 步进的小数 |

### 2.3 数据行实例

以下是一个正常连续段的示例片段：

```csv
Time(s),SampleIndex,Seq,ValidFlag,InterpFlag,GapLen,MissingBefore,Uc1(mV),...
4.980,498,498,1,0,0,0,1.23456,...
4.990,499,499,1,0,0,0,1.23500,...
5.000,500,500,1,0,0,0,1.23480,...
5.010,501,501,1,0,0,0,1.23510,...
```

## 3. 蓝牙丢包的数据体现（重点）

这是本文档的核心内容。当蓝牙透传链路发生丢包时，丢失会在记录数据中通过**多层机制**显式标记。

### 3.1 丢包检测原理：Seq 序号缺口

每个从 MCU 发出的 Raw 数据帧携带一个 16 位递增序号 `Seq`（在 35 字节帧内偏移 31-32，大端序）。PC 端每收到一帧，将其 `Seq` 与上一帧的 `Seq` 比较：

```
delta = (当前Seq - 上一帧Seq) % 65536
missing_before = delta - 1    # 若 delta=1 表示无丢包，delta>1 表示中间有缺失
```

例如：收到 `Seq=102` 后直接收到 `Seq=105`，则 `delta = (105-102) % 65536 = 3`，推断出 `missing_before = 2`，即 `Seq=103` 和 `Seq=104` 两帧丢失。

取模运算 `% 65536` 保证了序号从 65535 回绕到 0 时仍能正确计算差值。

PC 端还会对 `Seq` 做异常保护：只有半个 uint16 周期以内的前向差值会推进时间轴。若出现重复序号，或类似 `25018 -> 25016` 的小幅回退/乱序，软件会将该帧计为异常并跳过，不写入主 CSV 时间轴，也不会生成 655xx 行误判 `NaN`。真正的 `65535 -> 0` 回绕仍会正常接受。

### 3.2 丢包在主 CSV 中的四重标记

一旦检测到丢包，PC 端在主 CSV 中**同时**写入以下内容：

#### (a) NaN 占位行 — 保持时间轴连续

在真实样本行之前，先插入 `missing_before` 行 `NaN` 占位行，每行特征：

- `ValidFlag = 0`：标记为缺失
- 所有 13 个传感器字段填 `NaN`
- `SampleIndex` 按 100Hz 连续编号推算，保证时间轴不间断
- `Seq` 按上一有效 `Seq` 向后推算并 `& 0xFFFF` 保持在 0~65535 范围
- `GapLen = missing_before`：所有缺失行统一填写该 gap 的总长度

#### (b) 真实样本行的 `MissingBefore` 字段

紧接着缺失行之后写入真实样本行，其 `MissingBefore` 字段记录该样本前丢失了多少样本。若 `MissingBefore = 0` 表示无丢包。

#### (c) 真实样本行的 `ValidFlag = 1` 与 `GapLen = 0`

真实数据行 ValidFlag 始终为 1，GapLen 始终为 0——与占位行形成明确对照。

#### (d) 丢包率实时计算

每次丢包都会更新全局统计：

```
loss_rate = missing_count / expected_count
```

此丢包率在上位机面板实时显示，也记录在 `_status.csv` 中。

### 3.3 丢包在 Status CSV 中的对应体现

每秒一次的 STATUS 快照提供**固件视角**的补充证据：

| 诊断指标 | 含义 | 蓝牙丢包时的表现 |
|---|---|---|
| `PcMissingRaw` | PC 端累计缺失样本数 | 持续增长 |
| `PcMissingAfterTxDone` | MCU DMA 已完成发送但 PC 未收到的帧数 | **持续 > 0**，这是蓝牙丢包的强信号 |
| `PcRawInvalidDelta` | 相邻 STATUS 间 PC 解析失败的新增帧数 | 若 = 0 而 PcMissingAfterTxDone > 0：丢在 UART/BLE 透传层，非 PC 解析失败 |
| `TxDoneCounter` | MCU 侧 DMA 发送完成累计 | 正常递增，排除 MCU 发送侧问题 |
| `TxBusyCounter` | DMA 忙导致未启动发送 | 正常应为 0 或极小值 |

**关键判断**：若 `TxDoneCounter` 正常递增但 `PcMissingAfterTxDone > 0` 且 `PcRawInvalidDelta = 0`，则丢失必然发生在 BLE 透传链路——MCU 发完了但 PC 没收到，中间没有帧损坏（否则会有解析失败计数）。

### 3.4 时间轴示例：丢包如何呈现在文件中

假设设备侧 100Hz 采样，`SampleIndex=100` 时收到 `Seq=100`，下一帧直接跳到 `Seq=103`：

```
设备端实际采样:
  SampleIndex: ... 99, [100], [101], [102], [103], ...
  Seq:          ... 99,  100,   101,   102,   103, ...  (全部发出)
  
BLE 传输结果:          收到              丢失   丢失   收到
                      Seq=100           Seq=101 Seq=102 Seq=103

PC 端 CSV 输出:
  SampleIndex  Seq  ValidFlag  GapLen  MissingBefore  PPG_Green  PPG_Red  ...
  99            99   1          0       0              82341      45672    ...  ← 正常行
  100          100   1          0       0              82400      45710    ...  ← 正常行
  101          101   0          2                    NaN        NaN     ...  ← NaN占位行
  102          102   0          2                    NaN        NaN     ...  ← NaN占位行
  103          103   1          0       2              82890      46100    ...  ← 真实行，MissingBefore=2
```

可以看到：
- `Seq 101/102` 两行 `ValidFlag=0`，所有传感器值为 `NaN`
- 其 `GapLen=2` 表示该 gap 总共丢失 2 帧
- `Seq=103` 行 `ValidFlag=1`, `MissingBefore=2` 表示此前有 2 帧丢失

### 3.5 丢包模式与根因对应

| 丢包模式 | 典型表现 | 可能根因 |
|---|---|---|
| 零星 1-2 样本缺失 | 偶发 `MissingBefore=1`，无周期性 | 蓝牙瞬时干扰、DMA 偶发拥塞 |
| 周期性成片缺失 (30-50 样本) | 约 14-15s 周期出现 `ValidFlag=0` 连续 30-50 行 | 蓝牙从机密码认证超时断连（已于 2026-05 修复） |
| 持续大面积缺失 | `loss_rate > 5%`，持续 gap | BLE 信号弱、距离过远、天线问题 |
| 无 gap 但值异常 | `ValidFlag` 全为 1 但传感器值不合理 | 传感器故障或固件采样逻辑问题 |

## 4. 状态诊断文件：`<scenario><trial>_<SUBJECT>_<MMDD>_status.csv`

### 4.1 文件定位

该文件每秒记录一行，包含 MCU 固件的 16 路诊断计数器和 PC 端的链路统计。**用于诊断数据质量，不应作为生理信号输入。**

### 4.2 字段说明

#### 基础信息

| 字段 | 说明 |
|---|---|
| `RxTime(s)` | PC 端 wall-clock 接收时间（从录制开始计时） |
| `McuTime(ms)` | MCU 上电运行时间，单位 ms |

#### 固件诊断计数器

| 字段 | 语义 | 诊断用途 |
|---|---|---|
| `SampleCounter` | TIM16 触发 ADC 采样总次数 | 确认 MCU 采样节拍正常 |
| `FrameCounter` | MCU 主循环组帧次数 | 对比 SampleCounter 判断是否采样了但未组帧 |
| `TxStartCounter` | DMA 发送启动成功次数 | 对比 FrameCounter 定位发送启动瓶颈 |
| `TxDoneCounter` | DMA 发送完成回调次数 | **与 PC 接收数对比定位 BLE 丢包** |
| `TxBusyCounter` | DMA 忙导致发送失败次数 | 正常应为 0，持续增长说明 DMA 拥塞 |
| `TxErrorCounter` | UART/DMA 错误次数 | 正常应为 0 |
| `AdcDrdyCounter` | ADC 数据就绪中断次数 | 监控 ADC 采样链路 |
| `AdcErrorCounter` | ADC 状态机异常次数 | 正常应为 0 |
| `ImuErrorCounter` | IMU 读取异常次数（预留） | 正常应为 0 |
| `PpgFifoEmptyCounter` | PPG FIFO 空读次数 | 持续增长说明 PPG 采样不足 |
| `PpgFifoOverflowCounter` | PPG FIFO 逼近溢出次数 | 持续增长说明 PPG 采样速率过高或读取太慢 |
| `PpgFifoSampleTotalCounter` | PPG FIFO 非空读取周期累计拿到的样本数 | 与 Nonempty 相除得到非空周期平均样本数 |
| `PpgFifoNonemptyCounter` | PPG FIFO 非空读取周期次数 | 用于区分空读和真实采样周期 |
| `PpgFifoSingleSampleCounter` | 非空但只读取 1 个 PPG FIFO 样本的周期数 | 持续占比高说明多样本均值未充分发生 |
| `PpgFifoMultiSampleCounter` | 非空且读取 2 个及以上 PPG FIFO 样本的周期数 | `0x56/0x5F` 方案下应成为主要来源 |

#### PC 端统计量

| 字段 | 计算方式 | 诊断用途 |
|---|---|---|
| `PcReceivedRaw` | PC 累计解析成功的 Raw 帧数 | 基础接收计数 |
| `PcExpectedRaw` | 按 Seq 推算应收到的 Raw 帧数 | 对比 Received 得缺失数 |
| `PcMissingRaw` | `Expected - Received` | **总体丢包数** |
| `PcMissingAfterTxDone` | 从首次 STATUS 基线化后，`tx_done_delta - pc_received_delta` | **MCU 发完但 PC 没收到的帧数，蓝牙丢包的关键指标** |
| `TxInflight` | `tx_start_counter - tx_done_counter` | 正在发送中尚未完成的帧数 |
| `PcRawTotalCandidates` | PC 端串口流中识别出的 Raw 候选帧总数 | 监控接收字节流活跃度 |
| `PcRawInvalidCandidates` | 候选帧中校验失败的帧数 | **区分"字节没到"还是"到了但损坏"** |
| `PcRawInvalidDelta` | 相邻 STATUS 间新增无效候选帧数 | 与 gap 出现时机对比定位丢失环节 |

## 5. 标记点文件：`<scenario><trial>_<SUBJECT>_<MMDD>_markers.csv`

### 5.1 文件定位

这是用户在录制过程中通过点击 UI **标记按钮**手动记录的标记点文件。仅在一次录制中至少点击过一次 marker 后才会创建；未点击时不会产生空文件。每一行对应一次点击，标记点通过 `SampleIndex` 与主数据文件精确对齐。

### 5.2 字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| `Elapsed(s)` | float | 从录制开始到点击标记按钮的 wall-clock 时间，单位秒 |
| `SampleIndex` | int | 点击时刻对应的主数据样本索引，可直接与主 CSV 的 `SampleIndex` 列对齐 |
| `MarkerNo` | int | 标记点序号，从 1 开始累计，每次录制独立计数 |
| `Note` | string | 预留备注字段，当前默认为空 |

### 5.3 使用示例

```python
import pandas as pd

df = pd.read_csv("kaiji1_LYX_0710.csv")
markers = pd.read_csv("kaiji1_LYX_0710_markers.csv")

# 查看所有标记点及其对应的传感器数据
for _, m in markers.iterrows():
    sample = df[df["SampleIndex"] == m["SampleIndex"]]
    if len(sample) > 0:
        print(f"Marker {m['MarkerNo']} at {m['Elapsed(s)']:.1f}s: "
              f"PPG_Green={sample['PPG_Green'].values[0]}")
```

### 5.4 标记按钮交互

- 标记按钮位于 UI 工具栏录制按钮左侧，紫色底色
- 仅在录制中有效；未录制时点击不产生任何记录
- 点击后按钮文本更新为 `标记 (N)` / `Mark (N)`，实时显示累计标记次数
- 停止录制或清屏后计数自动归零

## 6. `NaN` 对下游算法的含义

主 CSV 中的 `NaN` 是**缺失占位符**，不是物理 0 值，也不是传感器饱和值，更不是上一有效样本的延续。它精确表示"该 100Hz 采样点没有收到有效传感器数据"。

下游算法处理建议：

1. **默认排除**：滤波、FFT、特征提取等运算前，通过 `ValidFlag=0` 过滤缺失行。
2. **窗口可信度**：若心率计算窗口内覆盖了连续 gap（`ValidFlag=0` 行 > 5），应将该窗口标记为低可信度，或在 gap 边界将窗口切分为独立段。
3. **不做隐式补全**：当前 `InterpFlag` 始终为 0，文件不做任何插值。若算法需要插值，应由算法显式读取 `ValidFlag` 后自行决定策略。
4. **频谱分析注意**：连续的 `NaN` 行在频谱上等效于不规则采样，直接做 FFT 会产生伪影。应先切除 gap 段。

## 7. 数据读取快速参考

### 读取有效数据（跳过缺失行）

```python
import pandas as pd

df = pd.read_csv("kaiji1_LYX_0710.csv")
valid = df[df["ValidFlag"] == 1]  # 仅有效样本
```

### 统计丢包情况

```python
total = len(df)
missing = (df["ValidFlag"] == 0).sum()
loss_rate = missing / total * 100
print(f"总行数: {total}, 缺失: {missing}, 丢包率: {loss_rate:.2f}%")
```

### 读取 Status 诊断

```python
status = pd.read_csv("kaiji1_LYX_0710_status.csv")
# 检查蓝牙丢包的关键指标
print(status[["RxTime(s)", "PcMissingAfterTxDone", "PcRawInvalidDelta"]].tail(10))
```

### 量化 PPG 小数精度和重复样本

2026-05-27 起, 仓库提供轻量诊断脚本用于复测 PPG 精度链路:

```powershell
python tools\monitor\ppg_quality_report.py kaiji1_LYX_0710.csv
```

重点看以下输出:

- `fractional_rows`: PPG 列中带小数的有效行数。Q4 协议生效后应大于 0。
- `triple_zero_diff_ratio`: Green/Red/IR 三路三元组与上一有效样本完全相同的比例。旧问题数据约为 `50.3%`。
- `sequence_missing_count`: 由 `Seq` 推断的缺失样本数。若为 0 但 `triple_zero_diff_ratio` 很高, 问题更偏向 PPG FIFO/平均/量化, 不是蓝牙丢包。

## 附录：完整数据流路径

```
MCU TIM16 100Hz ──> ADC 采样 ──> 主循环组帧 ──> UART DMA 发送 ──> BLE 透传 ──> PC 串口
                                                                                    │
                              ┌─────────────────────────────────────────────────────┘
                              ▼
                    PC 串口读取线程 (serial_reader.py)
                              │
                    ┌─────────┴─────────┐
                    ▼                   ▼
             Raw 帧解析            STATUS 帧解析
             (35字节/帧)           (69字节/帧, 1Hz)
                    │                   │
                    ▼                   ▼
          raw_quality.observe()   raw_quality.observe_status()
          检测 Seq 缺口            基线化对比 MCU vs PC
                    │                   │
                    ▼                   ▼
         timeline_packet_to_csv_rows()   status_packet_to_csv_row()
         生成有效行 + NaN占位行          生成诊断快照行
                    │                   │
                    ▼                   ▼
            <scenario><trial>_<SUBJECT>_<MMDD>.csv
            <scenario><trial>_<SUBJECT>_<MMDD>_status.csv
                    ▲
                    │
        RawDataPanel.add_marker()
        用户点击标记按钮 → Elapsed/SampleIndex/MarkerNo
                    │
                    ▼
            <scenario><trial>_<SUBJECT>_<MMDD>_markers.csv
```
