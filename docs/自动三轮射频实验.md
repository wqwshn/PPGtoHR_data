# 自动三轮射频对照：一次烧录，一次连续录制

入口为本工作树根目录 `start.bat`：`D:\PPGtoHR_data\.worktrees\ble-rf-control\start.bat`。
使用本工作树的新上位机录制；主工作区旧版不能识别新增实验事件帧。

## 操作流程

1. 固定电池、板子 USB 有线连接、姿态和气流条件；HJ-380 全程插着。
2. 在“固件配置与烧录”选择默认的 **自动三轮 · 实际连接30秒 / 保持复位30秒**。默认无 PPG、Raw 100 Hz、蓝牙初始化关闭。只需编译烧录一次。
3. 烧录后打开**有线 COM**，在“准备录制”的 60 秒倒计时结束前开始录制。若已错过第一段，不把不完整记录当完整三轮；停止该次录制，复位 MCU 后在新的60秒准备时间内重新开始录制。
4. 确认 HJ-380 能自动重连本板。随后无需插拔 dongle、操作复位或停止录制。程序自行完成三轮。
5. 界面显示“三轮完成 / COMPLETE”后再录约 5 秒，然后停止。保存同时间戳的主 CSV、`_status.csv`、`_rf_events.csv` 三个文件。

总时长约 **4 分钟 + 三次重连等待时间**；无法重连时可能更长。若一直显示等待连接，检查 HJ-380 状态和 PB12/BLE_STATE 接线，不能把等待段算作正常连接段。

## 实际执行规则

启动传感器采样后先留60秒准备期；期间蓝牙正常运行，也记录连接脚变化。准备期结束后，检测 BLE_STATE（PB12）持续高至少300ms，开始第1轮 NORMAL。

每轮顺序为：

`确认已连接 → NORMAL 30s → RESET_ASSERT（PB13拉高）→ RESET_HELD 30s → RESET_RELEASE（PB13拉低）→ 等待实际重连`

- 第1、2轮重连确认后，开始下一轮 NORMAL 30s。
- 第3轮保持复位结束后也释放复位并等待重连；确认连接后发 COMPLETE，保持正常运行，不再进入第4轮。
- NORMAL 中连接脚变低：记录 NORMAL_ABORT，该段不能用于完整30秒比较；停在等待状态，重连后重新计满本轮30秒，不消耗轮次。
- 复位保持期间应至少观测到一次连接脚低电平。若一直高，发 RESET_WARNING，并阻止其被误判为成功重连。需检查接线或模块复位行为。
- 等待重连超过120秒发 WAIT_WARNING，继续等待，绝不把超时当连接成功。
- PB12高/低记录的是连接状态脚的**软件观测时刻**，并非空口抓包时刻。NORMAL_START 比高电平边沿至少晚300ms；该300ms用于确认稳定。
- 300ms仅为连接确认，不代表热膜热稳定。本方案保持整次连续采集，后续分析可再排除各状态开头的过渡样本。

复位持续时间由 MCU 非阻塞时钟判断，主循环达到期限时执行，实际操作时刻写进事件；没有使用30秒 HAL_Delay，也不重启 MCU/ADC。实际持续时间应由事件时间差检查，而非假定恰好30000ms。

## 事件记录与对齐

新增 `AA EE ... 55` 的27字节事件帧，payload 带 XOR 校验。原35字节 Raw和53字节STATUS不变。事件在主循环产生，进入32槽队列；UART Raw DMA完成后，优先发已有STATUS，无STATUS时再发一条事件，不拼接到仍在传输的缓冲区。事件帧约2.34ms（115200、8N1），短于已有STATUS帧，避免每秒把STATUS和事件连续堆在同一个Raw后面。

CSV 的关键字段：

| 字段 | 含义 |
|---|---|
| Event | BOOT、LINK_HIGH/LOW、NORMAL_START/ABORT、RESET_ASSERT/RELEASE、COMPLETE、警告或 SNAPSHOT |
| McuTime(ms) | MCU生成事件的时刻，1ms计数；复位操作与软件观测同一次主循环记录 |
| SampleCounter | MCU采样触发计数，可与STATUS对齐，不是主CSV的本地SampleIndex |
| PhaseStart(ms) | 当前阶段开始时刻，可复核30秒区间 |
| Cycle / Phase | 当前轮次与 PREPARE、WAIT_LINK、NORMAL、RESET_HELD、DONE 阶段 |
| ConnectedPin | PB12软件读取值 |
| ResetCommand | 固件是否命令保持复位；不是模块引脚实测电压或RF功率测量 |
| EventId / QueueDropped | 事件和1Hz快照共用递增序号、固件队列溢出累计值，可审计记录完整性 |
| PcRxTime(s) | 事件被UI处理时距开始录制的时间，含串口和UI延迟，不用于精确判定复位时刻 |
| LastRecordedSampleIndex | PC收到事件时已记录的最新样本索引，仅作接收侧参考，不能替代MCU时间对齐 |
| RecordMarker | live为实时事件；recording_start_snapshot为开始录制时缓存的最近快照，不能当新的硬件操作 |

另有1Hz SNAPSHOT，即使稍晚打开上位机也能显示阶段；但快照不会补回开始录制前漏掉的历史事件。检查正常三轮至少各有3次有效NORMAL_START、RESET_ASSERT、RESET_RELEASE及最后COMPLETE；若有NORMAL_ABORT，需剔除中断段。确保QueueDropped=0，EventId连续（缓存起始快照例外）；MCU重启后计数会重置，不能跨重启直接相减。

记录持续追加并及时flush事件文件；常规固件未发送事件时仍只生成原有两个CSV。事件与Raw均通过相同有线串口接收。固件没有通过PC→MCU命令启动实验，以免依赖当前共用UART RX接线。

## 构建与验证

- 新固件：`build/rf-alternating/L452CEU6.elf`，同目录包含hex/bin和build.log。
- 重建脚本：`scripts/build_rf_pair.py`，同时重建正常、固定复位、自动三轮三种模式；参数与SHA-256见 `build/rf-pair-manifest.json`。
- 自动模式定义 `BLE_RF_EXPERIMENT=1, BLE_RF_DISABLED=0, ENABLE_BLE_CONFIG=0`，不恢复出厂、不重新写蓝牙参数。
- UI“编译并烧录”使用自己的 `build/desktop` 目录，按当前选择重新编译。
- `scripts/test_rf_controller.py` 将实际C状态机交叉编译后在软件ARM模拟器执行，覆盖三轮、重连等待、中途断连重计时、连接脚卡高与计时回绕。模拟器依赖只放在工作树 `.local/test-deps`。
- 上位机测试包括事件校验、分片混合串口流、CSV写入与关闭、自动模式编译参数。当前52项通过、2项FFT相关依赖测试跳过。

没有操作实际ST-Link或串口硬件，连接检测极性和复位连线仍需板端确认。保持复位不等于模块断电，也不等于实测RF为零；模块数字活动/功耗会一并变化，因此本实验定位的是BLE模块活动相关干扰，不能单独区分辐射和供电传导。
