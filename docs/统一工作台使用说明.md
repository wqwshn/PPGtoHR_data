# PPG 统一工作台

## 唯一日常入口

在项目根目录双击 **`start.bat`**。界面提供两个工作页面：

- **原始数据采集**：串口连接、波形、实时 FFT 心率、CSV 录制；不再提供独立在线心率页面。
- **固件配置与烧录**：选择固件参数、保存选择、检查 ST-Link、仅编译、编译并烧录。

旧入口 `tools/monitor/start_monitor.bat` 仍可使用，已转到同一工作台，优先使用项目 `.venv`，也支持已激活的 Conda/PATH Python，或通过 `PPG_PYTHON` 指定解释器。根目录原有多个 BAT 已归入 `scripts/`，其中旧 build/flash BAT 现在打开固件页，不会一打开就写入芯片。

## 原始数据采集

1. USB-TTL 或蓝牙提供 COM 口，选择串口后点击连接（115200，8N1）。普通 ST-Link/V2 的 SWD 不提供采集数据串口。
2. 默认保存到项目 `recordings/`。可用“选择保存路径”更改，完整路径显示在按钮悬浮提示中。
3. 点击“实验信息”填写场景、试次、受试者和日期并确认，然后点击录制；可用 Marker 标记事件，结束时点击停止。关闭工作台也会停止接收并关闭 CSV。
4. 无硬件时可点窗口右上角“开始模拟”，再次点击停止模拟。切换真实/模拟前必须先停止录制。

原始数据页内保留 FFT 心率、频谱 SNR 和计算耗时。热膜 CSV 同时保存原始值与 3 点中值，配套处理参数与按需 Marker/RF 文件。主 CSV 与 `_status.csv` 配套保存，模拟模式无固件 STATUS 包，因此状态文件只有表头。模拟计时不保证物理 100Hz，不应用模拟输出评估实际串口吞吐能力。

## 固件配置与烧录

| UI 选择 | 对应编译配置 | 默认 |
|---|---|---|
| PPG / IIC 通道 | `PPG_DEFAULT_CHANNEL` | 2 / IIC2 |
| 蓝牙配置 | `BLE_SINGLE25` 等 | 标准单帧 100 Hz / +2.5 dBm（未读回） |
| 蓝牙初始化 | `ENABLE_BLE_CONFIG` | 关闭 |
| 采集光模式 | `CURRENT_WORK_MODE` | 绿光 + 红光 + 红外 |
| SWD 速度 | OpenOCD `adapter speed` | 1000kHz |
| 输出与采样率（固定） | `ENABLE_RAW_DATA_PACKET=1`、`PPG_SAMPLE_RATE=100` | Raw 100Hz |

固定 100Hz 是为了与现有上位机 CSV 样本时间轴和 FFT 一致。50/125Hz 或板端 HR 结果模式需要另外适配上位机，不在此 UI 中提供。红光/红外只是固件采集光模式，不代表上位机会计算血氧值。

蓝牙初始化开启后，固件每次上电都会按 `main.c` 中已有指令配置模块；不是“本次烧录时只初始化一次”。本页面不会更改这些预设指令内容。

1. 确认板子型号是 **STM32L452CEU6**，时钟与项目 8MHz HSE 配置匹配。
2. 连接 SWDIO→PA13、SWCLK→PA14、GND→GND，建议 NRST→NRST。板子独立正常供电；正确处理 ST-Link VTref 电压参考，避免把供电输出混接。
3. 停止录制。点击“检查 ST-Link 连接”可检查探针与目标芯片（不写 Flash）；操作会断开采集串口。
4. 选择参数。“保存选择”只保存本机 JSON，不影响板子；“仅编译”只生成固件。
5. 点击“编译并烧录”，确认配置与目标后，按“配置→编译→烧录→校验→复位”执行。任一步骤失败即停止，不会在编译失败后烧录旧文件。
6. 操作进行中禁用配置控件，防止修改本次参数；关闭窗口会提示等待，避免中途终止烧录。

界面持续显示日志，完整日志写入 `.local/logs/`。构建产物在 `build/desktop/L452CEU6.{elf,hex,bin}`；同目录 `firmware-manifest.json` 记录参数、构建时间和 ELF SHA256。这个文件证明编译产物，不证明硬件已经烧录成功；以 UI 本次烧录结果为准。

当前使用 Debug 构建。上游异常处理函数在 Release 优化构建中存在链接问题，尚未在本任务修复。现有编译警告保留在日志中。

## 环境与验证

### ST-Link 传输配置兼容性

本机 OpenOCD 0.12 的 `interface/stlink.cfg` 使用 HLA 驱动，必须选择 `hla_swd`。工作台配置按 `adapter name` 判断：HLA 选择 `hla_swd`，其他驱动保留 `swd`。若出现 `Debug adapter doesn't support 'swd' transport`，表示配置阶段失败，尚未尝试连接目标芯片，不应据此判断供电或接线异常。

2026-09-15 已用工作台相同的 `init; shutdown` 命令实测：识别 STLINK V2J47S7、目标电压约 3.252 V、Cortex-M4，正常退出；此次只检查连接，未烧录。回归测试通过加载实际 OpenOCD 配置后直接退出检查兼容性，不要求连接硬件。

2026-09-15 合并验证：95 项 pytest 测试通过；标准三路 PPG、关闭 PPG、自定义蓝牙初始化+红光/红外、功率实验四种固件构建通过。采集页与烧录页完成离屏渲染检查，Windows 启动器通过 `--help` 检查。未执行硬件烧录、真实串口采集或重新验证实验结论。

双路采集的有线参考窗口使用只读串口接收，无线窗口保留 HJ-380 自动 MAC 绑定，两路录制目录分别为 `recordings/wired` 与 `recordings/wireless`。小窗口中的固件页可滚动查看。

统一入口优先使用项目或兼容父目录中的 `.venv/Scripts/python.exe`，再使用 PATH 的 Python；显式 `PPG_PYTHON` 优先。工具优先从 `.local-tools` 的 xPack 目录发现，其次查找 PATH。每台设备需自行确认 ST-Link 驱动。`scripts/dev_shell.bat` 可打开开发命令行。

重建 Python 环境（在根目录执行）：

```bat
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r tools\monitor\requirements.txt cmake ninja pytest
```

历史设备验证（2026-09-13，不代表当前设备状态）：通过 UI 实际编译了默认配置和 IIC1+开启蓝牙+红光/红外配置，检查编译宏与 ELF 哈希确实不同，之后恢复默认配置并重新编译；统一窗口模拟 CSV 录制通过。回归测试 44 通过，1 项已有的 Raw 文件说明文档字符串断言失败。当前没有对硬件执行实际烧录，真实串口和传感器仍需接板验证。

## 不使用 PPG（通道 0）

固件配置页的 PPG/IIC 通道新增“不使用 PPG”。对应 `PPG_DEFAULT_CHANNEL=0`：两路软件 IIC 引脚设为模拟输入/高阻，跳过 MAX30101 检测、初始化、模式配置、FIFO 和温度访问。光模式选择此时禁用、不生效。
原始包仍为 35 字节，PPG Green/Red/IR 所占的 bytes[22..30] 每帧固定填 0；ADC、ACC、GYRO、序号、XOR 和 STATUS 发送保留。PPG 未启用时不增加 FIFO 空/溢出计数。上位机 PPG/CSV 显示 0 是占位，不是测得的信号；协议不携带禁用标记，因此 FFT 可能显示信号弱/无结果，不能从全零数据独立判断硬件配置。默认通道仍为 2，需要选择通道 0 并重新编译烧录后才影响板子。
