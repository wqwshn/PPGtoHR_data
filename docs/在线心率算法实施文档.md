## 2026-10-21 MIMU 初始化结果持续上报

为解决电池供电、蓝牙晚连接错过启动日志的问题，固件保留本次启动的 MIMU 状态，通过每秒 STATUS 持续上报，供采集页独立显示。状态 0=初始化中；启动时在最多 5 次尝试内验证通过、完成原标定流程后置 1=启动成功；所有启动尝试失败且启用恢复时置 2=后台重试中；后台初始化通过并完成 200 ms 暖机后置 3=后台恢复成功；单次检测方案失败置 4=未就绪、自动重试关闭。初始化失败累计计数仍独立保留，启动成功时计数大于 0 表示曾在启动阶段重试。

STATUS 版本从 v2 升为 v3：帧头 AA DD，byte[2]=3，bytes[3..66] 原有 16 个 uint32 BE 字段原位保留，bytes[67..70] 新增 MIMU 状态 uint32 BE，byte[71] 为 bytes[2..70] 的 XOR，byte[72]=CC，总长 73 字节。DMA 与校验长度同步更新；Raw 35 字节及采样调度不变。上位机按版本选择帧长，兼容原有 69 字节 v1/v2，新版状态包需配套新版上位机。旧固件不包含显式状态，上位机显示未提供状态，不推断初始化成功。

状态在复位时清零，蓝牙断开重连不会修改设备状态。成功状态描述初始化路径，不代表本次标定成功或持续通信健康；运行中掉线自动探测仍不在此次范围。后台恢复继续使用有效历史零偏，否则零偏 0。上位机超过 3.5 秒未收到状态时标明过期，串口断开清除显示，防止把历史成功当作当前在线。

验证覆盖：执行真实 MIMU 初始化、恢复及 BuildStatusFrame 代码生成状态包，再用上位机解析，确认首次成功、启动重试成功、后台重试及后台恢复的状态与失败次数一致；模拟晚连接、旧版状态、串口任意分片、损坏校验、状态过期、重连、清屏、语言切换与模拟模式。完整 pytest 为 196 项通过；两种 MIMU 方案均 ARM 编译通过，尚待实板蓝牙验证。

## 2026-10-21 电池冷启动 MIMU 延时、重试与恢复

用户已修复短路，实测 ADC REFOUT 恢复到 2.5 V、带载 ±5 V 正常。随后发现：仅电池供电、连接负载时，启动可能无法识别 MIMU 并跳过标定；USB 与电池同时连接启动可正常标定，拔掉 USB 后仍正常。现象支持排查上电时序或电源建立过程，但尚不能证明电源波形异常。

旧流程只在启动时初始化一次。失败后虽仍可能由 ADC 中断发起 MIMU 读取，却不会重新初始化和验证配置，因而不能保证取得有效惯性数据。此次修改：

- 在原 MIMU 初始化位置额外等待 1000 ms；最多尝试 5 次，失败之间间隔 500 ms。身份与配置读回通过后，暖机 200 ms，保留原有加载历史零偏、静置标定流程。
- 启动 5 次均失败则继续 ADC/PPG 采集，ACC/GYRO 暂时输出零；主循环每 2000 ms 再尝试初始化一次。每次失败增加 STATUS 的 `imu_error` 计数。
- 后台初始化仍验证 AG 身份与关键配置；成功后用时间戳等待 200 ms，再加载有效的 Flash 历史零偏并启用惯性读取。没有有效历史零偏时使用默认零偏 0。运行中不执行长时间静置标定或写 Flash；下一次正常启动仍按原流程标定。
- 未就绪期间，ADC 采集中断不访问 SPI2，TIM16 也不操作 MIMU 片选，避免打断主循环中的初始化事务。MIMU SPI 单次传输超时改为 10 ms。后台初始化含原有 20 ms 复位等待及同步 SPI/日志发送，重试附近可能出现短暂发包间隔；200 ms 暖机等待不阻塞主循环。

恢复方案已改为独立可选项，默认关闭。上位机固件页新增“MIMU 启动方案”：默认“常规启动 · 单次检测”对应 `ENABLE_MIMU_RECOVERY=0`，只检测一次，无新增 1 秒等待和后台重试；成功后仍正常标定，失败后惯性字段暂为零。选择“电池冷启动 · 延时重试与后台恢复”对应 `ENABLE_MIMU_RECOVERY=1`，才启用上述延时和恢复。旧配置文件缺少 `mimu_recovery` 时按 0 处理，选择可保存；每次编译显式传入 0 或 1，避免 CMake 缓存残留。新板通信检查不使用此选项。

### 第二轮实测与电压排查

用户回传首版诊断实测：PPG 初始化前 SCL/SDA 均读高，但写地址 `0xAE` 未 ACK；初始化后 SCL 读低。ADC 七个寄存器在初始化后均读回 `00`，HAL 均返回成功。TIM16 每两秒增加200次，32秒内 `drdy=0 adc_state=0 frame=0 tx=0`，DRDY 数字输入一直读高。

### 带载 GV5 消失的实测确认

用户随后测得：不接外部 PPG、热膜时，U2的5V输出正常；接入后，该输出为0V。该证据已确认存在带载5V丢失，结合GV5与U9 AVDD/P2共轨，可直接解释此时ADC无法正常转换与PPG LED失去供电。还不能据此断定U2本体损坏、正常负载必然超过250mA，或所有IIC问题都只有这一原因。

优先保留+5V为0V时的状态，测U2的11/12脚BAT输入、7脚EN和9脚负输出（均相对AGND）。BAT正常且EN高时输出丢失，重点排查U2保护及其负载/外围；BAT明显跌落则先追溯电池、S1、接触和供电路径；EN低则追溯使能信号。若正负两轨都接近0，更符合双轨关断，但仍不能只凭此区分保护、控制或芯片故障。静态BAT正常也不能排除曾有瞬时跌落。

隔离测试顺序：每次断电更改连接，分别只接PPG、只接热膜及两者都接，重新上电后测GV5。某一路单独触发时查该支路供电/针序/短路/负载；单独均正常而合接失败时查总负载与瞬态余量。断开USB和电池、确认无电后再测外接板5V对地电阻，考虑电容充电及半导体导通影响，不以短暂蜂鸣判定短路。使用另一块正常主板作同负载、同供电条件对照，可区分新板供电链路与共同负载需求。

TPS65133启动阶段短路会限流；运行阶段触发短路判据会关闭双轨，须重新使能或输入重新上电恢复。若是后者，单纯拔掉负载不一定恢复；所以各组测试须建立新的上电周期。暂不通过固件自动反复重启电源来掩盖故障，也不直接向GV5并接外部电源进行试探。

用户进一步回传故障状态读数：U2 BAT输入为3.951V，EN为3.295V，负5V输出也为0V（正5V此前已测为0V）。静态输入位于推荐范围、使能为有效高，双轨同时无输出，因此优先查U2保护、输出负载和外围电路。该证据不支持当前EN被软件拉低或BAT一直缺电，但不能排除保护触发前瞬时输入跌落。尚不能仅凭这些静态值确认是短路保护、过热保护或芯片损坏。

下一步先在完全断电重启、无外接条件下同时确认正负5V（此前空载只明确正5V正常），再分别只接PPG、只接热膜测试。若手边具备电阻，也可在外接板全部断开时，断电接入GV5至AGND的已知电阻负载：先1kΩ（5mA、25mW），再100Ω且额定至少0.5W、优先1W（50mA、250mW）；每组重新上电观察双轨。轻负载即关断更支持新板U2/L1/L2/电容/焊接异常；已知电阻正常而实际模块失败则继续核对实际电流、启动浪涌、针序与接地，电阻测试不能复现所有瞬态。更低阻值或额定满载测试不在此步骤内。

## 2026-10-21 更换已知正常 U2 后的 ADC / AFE 排查

用户已从正常板取下U2并在问题板重焊，报告带外接负载仍掉电、无外接时有电压且能接收数据。更换降低U2本体异常的优先级，仍不能排除电感/电容、焊接、输入瞬态或负载。当前截图无外接时：Ut1平均约0.6mV、Ut2约2068.6mV、Uc1约316.1mV、Uc2约3.1mV。该截图不能单独证明ADC损坏或过流。

已用PCB网络、实际MUX采集和解析器交叉核对：Ut2来自U9 AIN2（5脚）=OUTD（U1 14脚/P2 7脚），相对U9 AINCOM（1脚）测量；不是UH2接口的直接读数。完整映射及原硬件文档中的通道/包偏移错误已修正在[ADC配置说明](hardware/ADS124S06配置说明.md)。原PCB AINCOM接地，旧固件注释提及实物飞线2.5V，两者必须区分。

第二路前端按设计参数，在供电、共模及输出均在线性区时：

```
A2 pin1 = UH2（负输入），pin4 = UC2（正输入），pin6 = Vref
Rg2 = 500Ω -> G_A2 = 1 + 19.8k/500 = 40.6
V_A2out = Vref + 40.6 × (UC2 − UH2)
OUTD = (1 + 39k/4.99k) × V_A2out − (39k/4.99k) × Vref
     ≈ Vref + 357.9146 × (UC2 − UH2)
UI Ut2（正向有效码、参考正常时）≈ OUTD − AINCOM
```

所以，Vref=2.5V时，若AINCOM接地，Ut2=2068.6mV对应OUTD约2.0686V、A2输出约2.4511V；若AINCOM已改2.5V，则对应OUTD约4.5686V、A2输出约2.7347V。拆掉外接热膜后UH2/UC2缺少外部直流通路，高增益前端可能形成任意偏置、漂移或饱和；不能要求两路Ut都归零。ADI手册要求AD8422输入偏置电流有直流回流路径：[AD8422](https://www.analog.com/media/en/technical-documentation/data-sheets/AD8422.pdf)。

最少万用表步骤：在无外接且5V稳定、界面正在更新的条件下，黑笔接AGND，依次测U9 26脚AVDD约5V、U9 23脚/C43非地端REFOUT约2.5V、U9 1脚AINCOM实际电压。随后红笔接U9 5脚AIN2，黑笔改接U9 1脚AINCOM，直接测差分；当前截图工作点应接近2.07V。差分与UI相符支持其来自真实模拟信号，不支持仅凭数值高就换ADC；不相符时再查参考、MUX、U9脚焊接和ADC读出。输入供电/基准均正常仍不符时，才提高ADC路径异常的优先级。

需要继续检查前端时，测A2 5脚对AGND应约−5V，以及A2 7脚输出，结合上述方程定位。U9 REFOUT同时给A1/A2的REF与U1参考反馈支路供电，异常低电压也可能来自参考负载或短接，不单独证明U9坏。当前ADC始终在GV5上，插入外接板主要改变外部供电负载与U1输出驱动；UI电压高不等于ADC供电电流大。仅用共轨电压/阻值无法把异常耗电唯一归到U9，后续若要证明U9过流，需要支路隔离或电流测量。

本轮针对读数归因与测量点修正文档，没有改写采样或协议。带载±5V已掉为0时的模拟读数不作为ADC正常测量依据。

### REFOUT 被5V误接的实物线索

用户按万用表步骤发现第二项REFOUT实测为5V，并进一步报告C43与C49附近的5V发生短接，准备维修。工程可直接核实C43非地端为V2.5、接U9 23脚REFOUT，另一端AGND；当前提取的PCB元件表未找到C49，不能补造其网络，具体短接点以实物为准。若确认是V2.5误连GV5，这是明确装配故障，应优先解除。

该误接很可能是主要原因或关键共因：参考输出被外部5V强制驱动，可能产生参考缓冲器异常电流；V2.5又给A1/A2 REF与U1参考反馈供电，5V会改变前端工作点，并可能在接入热膜后增加驱动负载。现有证据不足以量化电流或断言已触发哪一种保护。UI仍按2.5V换算，此时2068mV不能用于正常精度判断，也不应简单乘2补偿。已知好U2替换不解决下游误接，与此前现象一致。

维修在USB与电池均断开时进行，只清除误短接并恢复正确网络，保留C43正常参考去耦。修后先确认V2.5与GV5无直接硬短接，再空载上电核实GV5约5V、负轨约−5V、REFOUT约2.5V；正常后再断电接回外部模块验证双轨与持续数据。若REFOUT仍明显异常，应继续排除残余焊桥、参考负载或U9输出损伤。只有参考和带载电源恢复、采集持续稳定后，才能确认这一故障足以解释主要症状；空载前端悬空仍不要求Ut归零。

## 1. 项目概述

### 1.1 目标
将 MATLAB 离线心率解算算法 (PPG + LMS 自适应滤波 + FFT 融合) 部署到 STM32L452CEU6 单片机，实现 125Hz 采样、1Hz 心率输出的实时在线运行。

### 1.1.1 项目核心定位
本项目以 **HF 桥顶信号 (Ut1, Ut2) 作为自适应滤波参考信号**为核心路径，优先保证 LMS-HF 路径的心率估计质量。具体策略：

| 状态 | 融合选择 | 说明 |
|------|---------|------|
| **运动段** | **LMS-HF 路径** (主) | HF 桥顶信号与 PPG 的运动伪影高度相关，自适应滤波消除效果最优 |
| 静息段 | Pure-FFT 路径 | 信号干净时 FFT 精度最高 |
| LMS-ACC 路径 | 底线参考 | 始终计算，作为对比参考，不参与融合决策 |
| Pure-FFT 路径 | 底线参考 (静息主选) | 运动段作为参考，静息段作为主选 |

**后续算法优化应重点围绕 LMS-HF 路径展开**，包括 HF 信号质量评估、LMS 阶数/步长调优、频谱惩罚策略等。

## 2. 算法架构

### 2.1 整体流水线

```
TIM16 ISR (125Hz)
    |
    v
START_CONV pulse --> ADC DRDY ISR
    |                       |
    v                       v
ADC 4通道读取          ACC_6BytesRead()
    |                       |
    +--------+--------+------+
             |
             v
    Main Loop: ADC_1to4Voltage_flag == 4
             |
             +-- PPG FIFO 批量读取 + 均值 --> float ppg_val
             +-- ACC 16-bit --> float ax, ay, az
             +-- ADC/HF 16-bit --> float hf_val
             |
             v
    HR_PushSample() --> buf_1s_*[125] (每 tick 1 个 float)
             |
             v (当 sample_idx >= 125)
    flag_1s_ready = 1
             |
             v
    HR_RunSolver() [每秒执行一次]
             |
    1. 原始窗口平移 (memmove + memcpy, 5 通道)
    2. IIR 流式滤波 (仅新 125 点, 状态连续)
    3. 滤波窗口平移
    4. 运动检测 (ACC 幅值 std vs 阈值)
    5. 窗口填充检查 (需 >= 8 秒)
    6. 时延对齐 (去均值点积, +/-5 采样点)
    7. 路径A: LMS-HF (2级级联) + FFT + 频谱惩罚
    8. 路径B: LMS-ACC (3级级联) + FFT + 频谱惩罚
    9. 路径C: 纯FFT + Hamming窗 + 频谱惩罚
   10. 融合: 运动→LMS-HF, 静息→FFT (中值平滑跟随融合路径)
   11. 变化率限制
   12. 输出: hr_bpm (float)
             |
             v
    21字节心率结果包 --> UART DMA --> 蓝牙 (仅 ENABLE_RAW_DATA_PACKET=0)
    21字节原始数据包 --> UART DMA --> 蓝牙 (仅 ENABLE_RAW_DATA_PACKET=1, 互斥)
```

## 3. 设计决策记录

### 3.1 三路径融合策略: HF 为主，ACC/FFT 为底线参考
- **结论**: 保留全部 3 条路径。LMS-HF (桥顶信号参考) 为运动段主选路径，LMS-ACC 和 FFT 始终计算作为底线对比参考。预估算力 ~9ms/秒 (仅 1% CPU), 实时性无压力。
- **核心**: HF 桥顶信号 (Ut1, Ut2) 与 PPG 运动伪影的相关性优于 ACC，运动段自适应滤波消除效果更佳。
- **文件**: 已在算法初始化中分配了 HF (2级) 和 ACC (3级) 的完整 LMS 状态。

### 3.2 运动阈值: 混合方案
- **讨论**: 每次自动标定 vs 固定阈值？
- **结论**: 采用混合方案:
  1. 开机使用硬编码默认值 `Default_Motion_Th = 200.0f` (立即可用)
  2. 后台自动标定: 收集 8 个静息窗口的 ACC std 均值, 计算 `Motion_Th_Scale * baseline_std` 覆盖默认值
  3. 标定期间不阻塞心率输出, 使用默认阈值判断运动
- **风险**: 默认值需要根据实际硬件调试调整。不同佩戴方式可能影响基线。

### 3.3 数据发送模式 (互斥)
- **讨论**: 继续发送 125Hz 原始数据还是只发心率？
- **结论**: 两种模式互斥, 通过 `ENABLE_RAW_DATA_PACKET` 编译开关切换:
  - `0` (默认): 在线心率模式, 运行算法, 仅发送 1Hz 心率结果包 (0xAA 0xCC)
  - `1`: 原始数据模式, 不运行算法, 仅发送 125Hz 原始数据包 (0xAA 0xBB)
  - 心率包包含: 融合BPM/运动标志/3路径BPM/PPG信号强度/校准状态/时间戳/XOR校验
  - 互斥发送避免了两种数据包在 UART DMA 上冲突

### 3.4 IIR 滤波: 流式策略
- **关键**: 不能对 8 秒窗口重新滤波 (IIR 是因果滤波器)
- **方案**: 仅对新增 125 个样本滤波, 状态在 biquad 实例中自然传递
- **代价**: 需要维护独立的 `filt_*` 滤波后窗口 (额外 20KB RAM)

### 3.5 FFT 精度权衡
- **MATLAB**: 8192 点复数 FFT (分辨率 0.015 Hz = 0.9 BPM)
- **C**: 4096 点实数 RFFT (分辨率 0.031 Hz = 1.8 BPM)
- **评估**: 1.8 BPM 分辨率对心率检测足够, 节省一半内存

## 6. 关键技术细节

### 6.1 IIR 带通滤波器
- **类型**: 4 阶 Butterworth (2 个 biquad 节)
- **频率**: 0.5 - 5 Hz (对应 30-300 BPM)
- **系数来源**: `scipy.signal.butter(4, [0.5, 5], btype='bandpass', fs=125, output='sos')`
- **CMSIS-DSP 格式**: `[b0, b1, b2, -a1, -a2]` 每节 5 个系数
- **流式要求**: 每秒仅滤波新 125 样本, biquad 状态跨调用保持

### 6.2 LMS 自适应滤波
- **CMSIS-DSP API**: `arm_lms_norm_f32`
- **参数映射**: pSrc=参考噪声(ACC/HF), pRef=期望信号(PPG), pErr=去噪输出
- **级联**: HF 路径 2 级, ACC 路径 3 级
- **双缓冲区**: 级联使用 tmp/tmp2 交替, 避免读写冲突
- **自适应步长**: `mu = LMS_Mu_Base - corr/100` (corr 为相关系数)
- **自适应阶数**: `order = min(Max_Order, max(1, floor(|delay| * factor)))`

### 6.3 时延搜索 (ChooseDelay)
- **范围**: d = -5 到 +5 采样点
- **方法**: 对 PPG 和参考信号去均值后计算点积 (近似皮尔逊相关)
- **简化**: 相比 MATLAB 的 `corr()`, 在线版用去均值点积替代, 减少计算量
- **ref 缓冲区偏移**: ref 数组从索引 5 开始对齐, ±5 偏移通过调整起始索引实现

### 6.4 zscore 归一化
- **位置**: LMS 调用前, 在 scratch_a/b 上操作 (不污染 filt_* 数据)
- **步骤**: arm_mean → arm_offset(减均值) → arm_std → arm_scale(除标准差)
- **保护**: std < 1e-6 时钳制, 防止除零

### 6.5 频谱惩罚
- **目的**: 抑制运动频率及其二次谐波对心率检测的干扰
- **方法**: 参考 (ACC/HF) 信号 FFT 主峰 = 运动频率; PPG 峰值中接近运动频率的幅值乘以惩罚权重
- **参数**: 惩罚宽度 0.2 Hz, 惩罚权重 0.2

## 7. 数据输出协议

### 7.0 当前 Raw 数据包 (35 字节, 100Hz)

2026-04-24 起, 原始数据模式使用 35 字节 Raw 包, 在原 33 字节多光谱包基础上追加固件侧采样序号:

```
0-1    帧头                0xAA, 0xBB
2-9    ADS124S06桥压        4路uint16 BE
10-15  ACC X/Y/Z           int16 BE
16-21  GYRO X/Y/Z          int16 BE
22-30  PPG Green/Red/IR    3 bytes each, Q4均值, 上位机除以16还原为原始码值
31-32  Seq                 uint16 BE, Raw采样序号
33     XOR                 bytes[2..32]异或
34     帧尾                0xCC
```

`Seq` 在固件每生成一个 Raw 采样周期后递增, 即使 `HAL_UART_Transmit_DMA` 忙或返回错误也递增。上位机据此统计真实链路缺口: `missing_count`、`expected_count`、`Loss`、`RX Hz` 和 `DEV Hz`。

### 7.0.1 Raw 链路诊断 STATUS 包 (69 字节, 1Hz)

2026-04-30 起, 原始数据模式增加第一阶段链路诊断 STATUS 包。该包不替代 35 字节 Raw 数据包, 仅用于采集后定位丢失来源。

```
0-1    帧头                         0xAA, 0xDD
2      protocol_version             uint8, 当前为2
3-6    mcu_time_ms                  uint32 BE, HAL_GetTick()
7-10   sample_counter               uint32 BE, TIM16采样tick总数
11-14  adc_drdy_counter             uint32 BE, ADC DRDY中断次数
15-18  frame_counter                uint32 BE, Raw DATA组帧次数
19-22  tx_start_counter             uint32 BE, Raw DATA UART DMA启动成功次数
23-26  tx_done_counter              uint32 BE, Raw DATA UART DMA完成回调次数
27-30  tx_busy_counter              uint32 BE, Raw DATA发送时HAL_BUSY次数
31-34  tx_error_counter             uint32 BE, Raw DATA UART/DMA错误次数
35-38  adc_error_counter            uint32 BE, ADC状态异常次数
39-42  imu_error_counter            uint32 BE, IMU运行期异常次数
43-46  ppg_fifo_empty_counter       uint32 BE, PPG FIFO空读次数
47-50  ppg_fifo_overflow_counter    uint32 BE, PPG FIFO接近满/溢出风险次数

```

固件端只统计 Raw DATA 发送路径的 `tx_start_counter`、`tx_done_counter`、`tx_busy_counter` 和 `tx_error_counter`; STATUS 自身发送不计入这些 Raw 发送计数。阶段 B 修正后, STATUS 不再在主循环开头抢占 UART DMA, 而是在 Raw DATA DMA 完成回调后顺带发送, 避免 1Hz 诊断帧造成系统性 Raw `HAL_BUSY`。v2 额外导出 PPG FIFO 每次非空读取的样本数分布, 用于验证当前 `0x6F/0x3F` 或对照配置下 100Hz Raw 周期是否真的读取并平均多个 FIFO 样本。上位机录制时生成同名 `_status.csv`, 用于和 Raw CSV 一起分析 `sample_counter -> frame_counter -> tx_done_counter -> PC received` 的链路守恒关系。

### 7.0.2 HJ-131IMH BLE 配置

2026-05-01 起, 固件上电时可执行一次 HJ-131IMH 初始化配置。该逻辑由 `Core/Inc/main.h` 的 `ENABLE_BLE_CONFIG` 控制: `1` 表示上电复位并配置 BLE, `0` 表示跳过 BLE 配置。当前默认值为 `0`: 蓝牙模块已经完成一次恢复出厂、清空密码和 `FOREVER` 模式配置后，后续正常采集不应每次启动前重启或重新配置 BLE。仅当需要重新写入 BLE 参数时，临时改为 `1` 烧录一次，配置完成后再改回 `0`。

执行内容:

- 通过 `BLE_RST_Pin` 对 HJ-131IMH 执行硬件复位。根据手册 `h_RESET` 为高电平有效, 固件先拉高 100ms, 再拉低释放并等待 300ms。
- 发送唤醒序列 `0xAA 0xAA 0xAA 0xAA`。
- 先在当前 `115200bps` 下尝试发送 `<ST_FACTORY>`，兼容已经被本固件配置过的模块；随后将 MCU UART 切到出厂默认 `19200bps`，再次发送 `<ST_FACTORY>` 并复位，确保恢复出厂后的后续指令使用正确波特率。
- 手册说明若设置了蓝牙从机连接密码，主机连接后默认 15s 内必须通过 APP->BLE 通道发送密码，失败或超时会断开；因此在 `19200bps` 下发送 `<ST_CLEAR_SECRET>`，显式清空连接密码，避免进入 15s 密码认证流程。
- 在 `19200bps` 下设置 `ST_WAKE=FOREVER`, `ST_TX_POWER=+2.5`, `ST_NAME=HJ-131-LYX`, `ST_CON_MIN_GAP=75`，最后发送 `ST_BAUD=115200` 并将 MCU UART 切回 `115200bps`。该集合与参考工程实际配置的参数种类保持一致，暂不写入参考工程未配置的 `ST_CON_MAX_GAP` 和 `ST_CON_TIMEOUT`，用于对照排查周期性 BLE gap。
- 当前硬件调试口与 BLE 共用 UART, 且曾出现 USB 串口 TX 与 BLE TX 并接 STM32 RX 的情况; 因此固件不再执行 `RD_*` 读回和 `BLE_DIAG` 转发，避免产生误导性 timeout 日志。

## 不使用 PPG（通道 0）

固件配置页的 PPG/IIC 通道新增“不使用 PPG”。对应 `PPG_DEFAULT_CHANNEL=0`：两路软件 IIC 引脚设为模拟输入/高阻，跳过 MAX30101 检测、初始化、模式配置、FIFO 和温度访问。光模式选择此时禁用、不生效。
原始包仍为 35 字节，PPG Green/Red/IR 所占的 bytes[22..30] 每帧固定填 0；ADC、ACC、GYRO、序号、XOR 和 STATUS 发送保留。PPG 未启用时不增加 FIFO 空/溢出计数。上位机 PPG/CSV 显示 0 是占位，不是测得的信号；协议不携带禁用标记，因此 FFT 可能显示信号弱/无结果，不能从全零数据独立判断硬件配置。默认通道仍为 2，需要选择通道 0 并重新编译烧录后才影响板子。
